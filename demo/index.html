📋 The Problem Speckl Solves

AI code generators produce outputs at machine speed — but they can't explain why they made a decision. For regulated industries (medical devices, aerospace, critical infrastructure, finance), that's disqualifying. NIST SA-11 and the EU Cyber Resilience Act both require human-in-the-loop oversight for automated outputs.

Speckl is a judgement transport utility: it bridges the gap between "the AI says X is correct" and "here is a verifiable chain of evidence proving X is correct." Write your specification once — get code, proof, and provenance.

🟢 Live Demo: ToggleSwitch

The canonical simple example — a boolean state machine with two actions. Here's the whole thing:

Step 1 — SpeckDL Specification

// ToggleSwitch.speckdl — Simplest possible state machine spec ToggleSwitch { state { isOn: Boolean } init { isOn = false } action TurnOn() { require not isOn isOn = true } action TurnOff() { require isOn isOn = false } }

Step 2 — Compile (Real CLI Output)

$ speckl compile examples/ToggleSwitch.speck -o out/ 🧬 Speckl Compiler v0.3.1 Parsing: examples/ToggleSwitch.speck ✅ Generated 5 artifacts: out/ToggleSwitch.jsonld — PROV-O audit trail out/ToggleSwitch.cdx.json — CycloneDX SBOM out/ToggleSwitch.spdx.json — SPDX license metadata out/ToggleSwitch.ts — TypeScript state machine out/ToggleSwitch.wat — WebAssembly text format ✅ Compilation complete — all 5 artifacts generated

Step 3 — Generated TypeScript

// Generated TypeScript state machine export const enum ToggleSwitch_Action { TurnOn = "TurnOn", TurnOff = "TurnOff" } export class ToggleSwitch { // State variables private isOn: boolean; constructor() { // init {} this.state.isOn = false; } // Action: TurnOn TurnOn(): void { // require not isOn if (!this.state.isOn) throw new Error("Guard failed: not isOn"); // isOn = true this.state.isOn = true; } // Action: TurnOff TurnOff(): void { // require isOn if (this.state.isOn) throw new Error("Guard failed: isOn"); // isOn = false this.state.isOn = false; } }

⚖️ Speckl vs. TLA+

Speckl isn't trying to replace TLA+. It's a different tool for a different job:

TLA+ Speckl
Purpose Model checking (find bugs in designs) Compile spec to production code
Output Counterexamples, state space exploration TypeScript class + WASM module + audit trail
Verification Exhaustive state space search (TLC) Runtime guards from require/precondition blocks
Provenance None (design artifact only) PROV-O + CycloneDX + SPDX per compilation
Use case "Is my design correct?" "Is what I deployed traceable to what I specified?"

The two tools are complementary. Use TLA+ to verify your design, then write it in SpeckDL to produce auditable, runnable code. Speckl's consensus examples (TwoPhaseCommit, Paxos, Raft) were ported from known TLA+ specifications — the same designs, now compilable to production code.
