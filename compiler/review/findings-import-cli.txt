Reviewer findings: speckl --root
Question: does every behaviour that is correct on the target stay correct on this branch?

Target: the import-wiring slice. compileSpec already took rootDir. The CLI did not pass it. Working: speckl --root sets that option.

Without --root, an import whose real path leaves the entry file's directory fails closed. --root widens the directory. --root / widens it to the whole filesystem. Absolute import paths stay rejected. A missing file, a cycle, a duplicate alias, an absolute path, a --root that is a file, and a --root that does not exist each exit non-zero. The missing-root error is `cannot read import root`. The message for a missing import includes `<file>:<line>`. No generated file is written for those failures.

Example files have no imports, so their compiled output is unchanged. The README, SPEC, and CHANGELOG name the flag. That text does not by itself change compiled output.
