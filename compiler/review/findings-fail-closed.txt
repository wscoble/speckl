Reviewer findings: fail closed on malformed spec structure
Question: why does this parser reject input the line walker accepted?

The line walker silently accepted a missing `}`, an extra `}`, text after `}`, an unrecognized member, and `§`. It returned an AST and did not say the spec was broken. A spec with those errors compiled as if the bad text were not there. This change turns that off. `MATCH_LINE_WALKER` in `compiler/src/rd-parser.ts` is false. The token parser's error is the result. Example specs still lower to the same IR. Rejecting malformed structure does not change those files' output.

`compiler/src/__tests__/parser-malformed.test.ts` runs the line walker and `parseSpeck` on the same source. The walker column is the before. This parser's message is the after.

| --- | --- | --- | --- |

| `speck A {\n}\n}` | accepts `A`, 0 members, end line 2 | `extra "}"` at line 3 column 1 | rejects an extra close the walker ignored |

| unterminated `"` | `unterminated string`, no column | the same text plus ` (column 8)` | adds the column to an unterminated string the walker already rejected |

A `}` inside a string is still a string, not an extra close. That test is `does not treat a brace inside a string as an extra close`.

This does not change example output. It does not resolve `import`. It does not change what Go drops inside `if` and `for`.
