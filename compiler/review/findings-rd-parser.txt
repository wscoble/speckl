Reviewer findings: recursive-descent parser vs the output-hash branch
Question: does every behaviour that is correct on the target stay correct on this branch?

Mechanical equivalence, IR. `compiler/src/__tests__/walker-vs-rd.test.ts` runs the output-hash line walker (the copy in `compiler/src/line-walker/`) and `parseSpeckDocument` on every `examples/*.speckdl` file and every `.speckdl` fixture under `compiler/src/__tests__/fixtures` and `compiler/__tests__/fixtures`. Both ASTs go through the same `lower()` with `resolveImports: false`. `JSON.stringify` of the two IR values is equal for all 22 files, including `KafkaKRaft.speckdl` and `OAuth2AuthorizationCode.speckdl`. An empty file and a comment-only file also lower to the same IR.

Malformed input is the same program. `walker-vs-rd.test.ts` runs both parsers on a missing final `}`, an extra `}`, text after `}`, an unrecognized member, `§`, `→`, an unterminated string, `speck` with the name on the next line, a second speck on one line, text after a member `}`, a misspelled member, a misspelled top-level name, and `speck 9A`. The error text matches, including an empty string when both accept. When both accept, `JSON.stringify` of the two ASTs matches. An unterminated string is `Parse error at bad.speckdl:2: unterminated string` from both, with no column. `MATCH_LINE_WALKER` in `compiler/src/rd-parser.ts` is what returns the line walker's AST when the token parser throws. Specs the token parser accepts do not take that path.

Output hash. The target compiler is the output-hash branch. The working compiler is this branch. Both hash every `examples/*.speckdl` file at `-t all` and `-t all-ir` to the same sha256:

9bdc5a8a21f64044b1200534581f67a08a8fb8aea206cdb61c365a8b1ca18bc1

That constant is `OUTPUT_SHA256` in `compiler/src/__tests__/compile-pipeline.test.ts` on the target branch and on this branch. The test builds one map. Each example is its own key, `<file> -t all` and `<file> -t all-ir`, and the value is that run's file digests. The hash is sha256 of `JSON.stringify` of the whole map. One changed example moves the hash. The hash did not move, so every example's output is identical, not only the combined digest. The output-hash pin is unchanged on purpose.

`parseSpeck` calls `parseSpeckDocument` in `compiler/src/rd-parser.ts`, which calls the token lexer. `compiler/src/__tests__/parser-intended-diff.test.ts` checks the shapes a later change will fix, and they still match the line walker.

This PR does not reject a spec the line walker accepted. `parser-malformed.test.ts` stores the walker's AST for a missing `}`, an extra `}`, text after `}`, an unrecognized member, and `§`. A `}` inside a string is not an extra close. File-level `import` is syntax-checked and not resolved. Go still drops an `else if`, a nested `if`, a `for` inside an `if`, and a `require` inside an `if`.

The README, SPEC, and CHANGELOG describe this parser. That text does not itself change compiled output.
